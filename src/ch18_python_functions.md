# Глава 18. Функции, замыкания, декораторы

Функция в Python — не просто блок кода, а объект: у неё есть атрибуты, её можно передать, вернуть, обернуть и сохранить в словаре. Из этого следуют три инструмента, на которых держится почти весь инфраструктурный код: декораторы (повторные попытки, замер времени, проверка прав, кэш), замыкания (фабрики обработчиков и конфигураторов) и генераторы (потоковая обработка логов и ответов API без загрузки в память целиком).

Глава разбирает сигнатуры и правила передачи аргументов, области видимости и `nonlocal`, устройство замыканий и их классическую ловушку с поздним связыванием, декораторы с параметрами и без, `functools.wraps` и `lru_cache`, а также итераторы и `yield`. Финал — рабочий декоратор `retry` с экспоненциальной задержкой, тот самый, что в главе 21 будет расширен до HTTP-клиента. Примеры проверены на CPython 3.14.9.

## Сигнатуры: позиционные, keyword-only и «всё остальное»

Полная форма сигнатуры выглядит так: `def f(pos_only, /, normal, *args, kw_only, **kwargs)`. Слэш отделяет параметры, которые можно передать только позиционно, звёздочка — начало секции, где аргументы передаются только по имени, `*args` собирает лишние позиционные в кортеж, `**kwargs` — лишние именованные в словарь.

```python
def deploy(env, /, service, replicas=2, *, dry_run=False, **labels):
    print(env, service, replicas, dry_run, labels)

deploy("prod", "api", 3, dry_run=True, team="core", tier="web")
deploy(env="prod", service="api")
```

```text
prod api 3 True {'team': 'core', 'tier': 'web'}
TypeError: deploy() missing 1 required positional argument: 'env'
```

Второй вызов падает, потому что `env` объявлен позиционным. Сообщение выглядит странно — «не хватает `env`», хотя он передан, — но смысл точный: именованный аргумент `env` не может заполнить позиционный параметр, а `**labels` его не ловит. Позиционные параметры нужны, когда имя — деталь реализации и вы не хотите, чтобы его использовали как контракт (частая практика в стандартной библиотеке).

Значения по умолчанию вычисляются один раз, при выполнении `def`, — отсюда ловушка изменяемого аргумента из главы 17. Здесь важно следствие для API: значение по умолчанию должно быть неизменяемым или `None`. Порядок параметров тоже регламентирован: параметры без значения по умолчанию идут до параметров со значением, иначе получается двусмысленность при вызове.

Вызов, в свою очередь, поддерживает распаковку: `f(*args, **kwargs)` передаёт содержимое последовательности и словаря. Это основа универсальных обёрток — декоратор не знает сигнатуры оборачиваемой функции и просто пробрасывает всё насквозь.

## Области видимости и `nonlocal`

Имена разрешаются по правилу LEGB: локальная область (Local), затем объемлющие функции (Enclosing), затем модуль (Global), затем встроенные (Builtins). Чтение работает наружу автоматически, запись — нет: присваивание внутри функции создаёт локальное имя, если оно не объявлено `global` или `nonlocal`.

```python
counter = 0

def bump():
    global counter
    counter += 1

bump(); bump()
print(counter)
```

```text
2
```

Без `global` строка `counter += 1` бросила бы `UnboundLocalError` (чтение локальной переменной до присваивания), потому что присваивание делает имя локальным на всю функцию. Это одна из самых частых ошибок при правке чужого кода: достаточно добавить присваивание, и функция перестаёт видеть глобальную переменную.

`nonlocal` делает то же для ближайшей объемлющей функции:

```python
def make_counter():
    n = 0

    def inc(step=1):
        nonlocal n
        n += step
        return n

    return inc

c = make_counter()
print(c(), c(5), c())
```

```text
1 6 7
```

Глобальное состояние в продакшене — источник гонок и «плавающих» тестов: два запроса делят один счётчик. Замыкание предпочтительнее, потому что состояние создаётся на каждый экземпляр функции и не видно снаружи.

## Замыкания и позднее связывание

Замыкание (closure) — функция, которая помнит переменные из области, где была создана, даже после выхода из неё. В примере выше `inc` держит ячейку (cell) с `n`: `make_counter()` завершилась, а её локальная переменная жива, пока жива `inc`.

Классическая ловушка — замыкание в цикле захватывает переменную, а не значение:

```python
funcs = [lambda: i for i in range(3)]
print([f() for f in funcs])
funcs = [lambda i=i: i for i in range(3)]
print([f() for f in funcs])
```

```text
[2, 2, 2]
[0, 1, 2]
```

В первом случае все три лямбды смотрят в одну ячейку `i`, которая к моменту вызова равна 2. Во втором значение фиксируется значением по умолчанию — оно вычисляется при создании каждой лямбды. Третий способ — `functools.partial` — читается лучше, чем `lambda i=i:`, когда аргументов несколько.

Практический смысл: в цикле по обработчикам, хендлерам или таймерам нельзя регистрировать замыкание, которое читает переменную цикла, если она изменится до вызова. Это регулярно всплывает в коде, где цикл навешивает колбэки на события.

## Декораторы

Декоратор — функция, которая принимает функцию и возвращает функцию. Синтаксис `@decorator` — просто сахар: `def f(): ...` плюс `f = decorator(f)`.

```python
import functools

def logged(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f"-> {func.__name__}{args}{kwargs}")
        result = func(*args, **kwargs)
        print(f"<- {result!r}")
        return result
    return wrapper

@logged
def add(a, b):
    return a + b

add(2, 3)
print(add.__name__, add.__doc__)
```

```text
-> add(2, 3){}
<- 5
add None
```

`functools.wraps` копирует на обёртку `__name__`, `__doc__`, `__module__`, `__qualname__`, `__dict__` и `__wrapped__`. Без него `add.__name__` стало бы `wrapper`, сломались бы логи, трассировки, автодокументация и `inspect.signature`. Правило простое: любой декоратор оборачивает через `functools.wraps`, исключений нет.

Декоратор с параметрами — это функция, возвращающая декоратор: три уровня вложенности. Первый уровень принимает настройки, второй — функцию, третий — аргументы вызова.

```python
import functools, time

def retry(attempts=3, base=0.1, factor=2.0, exceptions=(Exception,)):
    def decorate(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            delay = base
            for attempt in range(1, attempts + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as exc:
                    if attempt == attempts:
                        raise
                    print(f"  attempt {attempt}: {exc}; sleep {delay:.2f}s")
                    time.sleep(delay)
                    delay *= factor
        return wrapper
    return decorate
```

Разбор по частям. `delay` начинается с `base` и умножается на `factor` после каждой неудачи: 0,05 → 0,1 → 0,2 с. На последней попытке исключение пробрасывается наружу — декоратор не глотает ошибку, а лишь даёт шанс. `exceptions` ограничивает, что вообще считается временной ошибкой: ретраить `ValueError` из-за кривого конфига бессмысленно, ретраить `ConnectionError` — обязательно. `functools.wraps` сохраняет имя, поэтому в логах и метриках видно `fetch_config`, а не `wrapper`.

Проверка на функции, которая падает дважды:

```python
calls = {"n": 0}

@retry(attempts=4, base=0.05)
def fetch_config(url):
    calls["n"] += 1
    if calls["n"] < 3:
        raise ConnectionError("connection reset by peer")
    return {"url": url, "ok": True}

print(fetch_config("https://cfg.internal/app"), fetch_config.__name__)
```

```text
  attempt 1: connection reset by peer; sleep 0.05s
  attempt 2: connection reset by peer; sleep 0.10s
{'url': 'https://cfg.internal/app', 'ok': True} fetch_config
```

Три вызова, суммарная пауза 0,15 с, результат получен. В реальном коде сюда добавляют джиттер (случайную добавку к задержке), чтобы после падения общего ресурса клиенты не били по нему синхронно, и общий дедлайн: если бюджет запроса 10 с, четыре попытки с растущей задержкой могут его превысить. Ещё одна тонкость: ретрай допустим только для идемпотентных операций — повтор `POST`, который уже создал ресурс, создаст второй.

Декоратор может быть и классом с `__call__`, что удобно, когда нужно состояние (счётчики, конфиг). Минус — теряется прозрачность для `inspect`, поэтому классы-декораторы чаще применяют к методам с явным `__get__`, а это уже отдельный уровень сложности.

## `lru_cache` и мемоизация

`functools.lru_cache` кэширует результаты по аргументам: ключ — кортеж аргументов, значение — результат.

```python
@functools.lru_cache(maxsize=None)
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

t0 = time.perf_counter()
print(fib(80), f"{time.perf_counter() - t0:.4f}s")
print(fib.cache_info())
```

```text
23416728348467685 0.0000s
CacheInfo(hits=78, misses=81, maxsize=None, currsize=81)
```

Без кэша `fib(80)` потребовал бы порядка 2^80 вызовов — астрономическое время; с кэшем это 81 вычисление и 78 попаданий, доли миллисекунды. `maxsize=None` означает неограниченный кэш; `maxsize=128` ограничивает и вытесняет давно использованные записи (LRU — least recently used).

Ограничения существенные. Аргументы должны быть хешируемыми: список или словарь в аргументах даст `TypeError: unhashable type`. Кэш живёт в памяти процесса и не разделяется между воркерами, поэтому после деплоя каждый процесс прогревается заново. Кэш не знает об изменении внешнего состояния: если функция читает файл или ходит в API, закэшированный ответ устареет. Для «вычислить один раз» есть `functools.cache` — тот же `lru_cache(maxsize=None)` с более коротким именем. И помните: декоратор на методе экземпляра держит ссылку на `self`, что мешает сборке мусора, — для методов нужен `lru_cache` на уровне класса или кэш по значимым полям.

## Генераторы и итераторы

Итератор — объект с `__next__`, который выдаёт элементы по одному и по исчерпании бросает `StopIteration`. Генератор — функция с `yield`, компилируемая в итератор: вызов не выполняет тело, а возвращает объект, хранящий кадр со всеми локальными переменными.

```python
def read_lines(path):
    with open(path, encoding="utf-8") as fh:
        for line in fh:
            yield line.rstrip("\n")

def parse(lines):
    for line in lines:
        key, _, value = line.partition("=")
        if value:
            yield key.strip(), value.strip()

print(dict(parse(read_lines("app.env"))))
```

```text
{'host': 'db', 'port': '5432'}
```

Файл `app.env` содержит три строки: `host=db`, `broken`, `port=5432`. Строка без `=` отброшена условием `if value`. Конвейер обрабатывает файл построчно: в памяти одновременно одна строка, а не весь файл, — на гигабайтном логе это разница между работой и `MemoryError`. Генераторы компонуются: выход одного становится входом другого, а вычисления начинаются только при первом `next()`.

`yield from` делегирует итерацию вложенному итератору и пробрасывает `send`/`throw`:

```python
def chain(*iterables):
    for it in iterables:
        yield from it

print(list(chain([1, 2], (3,), "ab")))
```

```text
[1, 2, 3, 'a', 'b']
```

Генератор одноразовый: после исчерпания повторный проход даёт пустоту. Если данные нужны дважды, материализуйте их (`list(...)`) или создайте генератор заново. Генератор также умеет `close()` — при этом в него «вбрасывается» `GeneratorExit`, и блоки `finally` выполняются, что позволяет освобождать ресурсы.

## Типичные ошибки

1. **Изменяемое значение по умолчанию.** `def f(x, acc=[])` — один список на все вызовы, потому что значение вычисляется при `def`. Лечение — `None` и создание внутри.
2. **Забытый `functools.wraps`.** Обёртка получает имя `wrapper`; логи, метрики и трассировки указывают не на ту функцию, а `inspect.signature` показывает `(*args, **kwargs)`. Механизм — декоратор буквально подменяет объект функции.
3. **Замыкание в цикле.** `[lambda: i for i in range(3)]` даёт три функции, читающие одну ячейку, — все вернут последнее значение. Лечение — параметр по умолчанию или `partial`.
4. **`global` вместо возврата значения.** Функция, меняющая модульскую переменную, не тестируется изолированно и ломается при параллельных вызовах. Механизм — состояние живёт дольше вызова и делится между потоками.
5. **Ретрай неидемпотентной операции.** Повтор `POST /orders` после таймаута создаёт второй заказ. Механизм — таймаут не означает, что сервер не выполнил операцию.
6. **`lru_cache` на функции с побочными эффектами.** Кэшируется результат чтения файла или API, и данные «замерзают» до перезапуска процесса. Механизм — ключ кэша не включает внешнее состояние.
7. **Исчерпанный генератор.** Второй `for` по тому же объекту молча не выполняется ни разу; сумма равна нулю. Механизм — итератор хранит позицию и не перезапускается.

- [ ] У каждого декоратора в проекте есть `@functools.wraps(func)`.
- [ ] Ретраи ограничены числом попыток, списком исключений и общим дедлайном; операции идемпотентны.

## Упражнения

1. **Разминка.** Напишите `def tag(name, /, *, prefix="app", **attrs)`, которая собирает строку `prefix:name` и список атрибутов. Добейтесь, чтобы вызов `tag(name="x")` падал с `TypeError`, и объясните сообщение.
2. **Замыкание.** Реализуйте `make_limiter(rate)` — фабрику функций, каждая из которых помнит своё состояние и возвращает `True` не чаще `rate` раз в секунду (используйте `time.monotonic`).
3. **Декоратор.** Добавьте к `retry` параметр `jitter` (случайная добавка к задержке) и общий дедлайн `deadline`. Проверьте, что при исчерпании дедлайна возвращается последняя ошибка, а не бесконечное ожидание.
4. **Кэш.** Оберните функцию, читающую конфиг из файла, в `lru_cache` и покажите, как получить устаревшие данные. Предложите схему инвалидации по `mtime`.
5. **Генераторы.** Напишите конвейер «чтение лога → фильтр по уровню → агрегация по коду ответа», который обрабатывает файл 1 ГБ с постоянным потреблением памяти. Измерьте пик через `tracemalloc`.
