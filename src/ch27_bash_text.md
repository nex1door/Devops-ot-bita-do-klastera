# Глава 27. Текст: grep, sed, awk, jq, xargs, find

Девяносто процентов работы DevOps-инженера с текстом — это «найти, вырезать, посчитать, заменить». Логи, конфиги, вывод `kubectl`, JSON из API, списки файлов: всё это потоки строк, которые нужно превратить в ответ на конкретный вопрос. Unix даёт для этого набор маленьких инструментов, каждый из которых делает одно действие и умеет читать stdin и писать в stdout. В этой главе — grep и sed для поиска и замены, awk для полей и агрегатов, jq для JSON, find и xargs для работы с файлами, а также конвейеры, которые решают реальные задачи и не ломаются на пробелах в именах. Отдельно разберём, чего этими инструментами делать не стоит.

## grep: поиск и коды возврата

`grep` печатает строки, совпавшие с шаблоном. Базовый шаблон — BRE; с `-E` включается расширенный (ERE), с `-P` — PCRE, если сборка его поддерживает. Все примеры ниже работают с `access.log` в формате combined плюс время ответа: поле 1 — IP, 7 — путь, 9 — код ответа, 10 — байты, 11 — секунды.

```bash
$ grep -c '" 5[0-9][0-9] ' access.log
2
$ grep -ci 'timeout' /var/log/syslog
0
```

Ключевые флаги:

| Флаг | Действие |
|---|---|
| `-i` | игнорировать регистр |
| `-v` | инвертировать: строки без совпадения |
| `-c` | только число совпавших строк |
| `-n` | номер строки |
| `-o` | печатать только совпавшую часть |
| `-r` / `-R` | рекурсивно по каталогу (R идёт по симлинкам) |
| `-l` | только имена файлов |
| `-A n` / `-B n` / `-C n` | контекст после/до/вокруг |
| `-I` | пропускать двоичные файлы |

Коды возврата — часть контракта: 0 — совпадения есть, 1 — совпадений нет, 2 — ошибка (нет файла, битое регулярное выражение). Поэтому `grep` в условии работает естественно:

```bash
if grep -q '^PermitRootLogin yes' /etc/ssh/sshd_config; then
    echo "root-логин по паролю разрешён" >&2
fi
```

`-o` превращает grep в экстрактор. Из лога доступа можно достать методы и пути:

```bash
$ grep -oE '(GET|POST|DELETE) [^ ]+' access.log | sort | uniq -c | sort -nr
      4 GET /api/orders
      1 POST /api/orders
      1 GET /static/app.js
      1 GET /healthz
      1 GET /api/users/7
      1 DELETE /api/orders/41
```

`grep -r` без ограничений опасен: он заходит в `.git`, `node_modules` и виртуальные окружения. Ограничивайте через `--include='*.yaml'` и `--exclude-dir={.git,node_modules,venv}`. Для поиска по коду лучше `rg` (ripgrep), но в минимальном контейнере часто есть только grep — тогда эти флаги обязательны.

## sed: замена и диапазоны

`sed` — потоковый редактор. Программа состоит из адресов и команд: `[адрес[,адрес]]команда`. Главная команда — `s/что/на что/флаги`, где `g` заменяет все вхождения в строке, а не первое.

```bash
$ sed -E 's/^([0-9.]+) [^"]*"(GET|POST|DELETE) ([^ ]+) [^"]*" ([0-9]{3}).*/\4 \2 \3/' access.log
200 GET /api/orders
404 GET /api/orders/42
201 POST /api/orders
200 GET /healthz
500 GET /api/orders
304 GET /static/app.js
500 GET /api/orders
200 GET /api/users/7
204 DELETE /api/orders/41
200 GET /api/orders
```

Здесь `-E` включает ERE, группы `(...)` подставляются как `\1`…`\9`. Тот же результат без `-E` потребовал бы экранировать каждый `(`, `)`, `{`, `}` и `|`.

Диапазоны адресов выбирают фрагмент файла. `sed -n '/10:13:/,/10:14:02/p'` печатает всё от первой строки, содержащей `10:13:`, до строки с `10:14:02` включительно; `-n` подавляет автоматический вывод, иначе строки напечатались бы дважды.

Типичные операции:

```bash
sed -n '1,20p' file              # первые 20 строк
sed -n '$p' file                 # последняя строка
sed '/^#/d; /^$/d' file          # убрать комментарии и пустые строки
sed -i.bak 's/listen 80;/listen 8080;/' nginx.conf   # замена с бэкапом
sed -E 's/[[:space:]]+$//' file  # обрезать хвостовые пробелы
```

`-i` редактирует файл на месте. GNU sed создаёт временный файл и переименовывает его, поэтому права и владелец сохраняются, а вот жёсткие ссылки рвутся, а симлинк заменяется обычным файлом. На BSD/macOS `-i` требует аргумент: `sed -i '' 's/a/b/' file`. В скриптах, которые должны работать везде, либо не используйте `-i`, либо проверяйте платформу.

Символ `&` в замене означает всё совпадение, `\&` — литеральный амперсанд. Это ловушка при замене URL с query-строкой.

## awk: поля, условия, агрегаты

`awk` — это маленький язык программирования, а не «grep с колонками». Программа состоит из пар `шаблон { действие }`; выполнение идёт по строкам, `$0` — вся строка, `$1`…`$NF` — поля, разделитель задаётся `-F` или переменной `FS`.

```bash
$ awk '{b += $10; n++} END {printf "%d запросов, %.1f KB, средний %.0f B\n", n, b/1024, b/n}' access.log
10 запросов, 2.5 KB, средний 251 B
```

Здесь нет ни одной внешней команды: awk сам прочитал файл, сложил байты из десятого поля и посчитал среднее. Блок `END` выполняется один раз после последней строки.

Подсчёт по группам — через ассоциативный массив:

```bash
$ awk '{c[$9]++} END {for (s in c) printf "%s %d\n", s, c[s]}' access.log | sort -k2 -nr
200 4
500 2
404 1
304 1
204 1
201 1
```

Порядок обхода массива в awk не определён — поэтому `sort` в конце обязателен, иначе вывод будет меняться от запуска к запуску.

Условие в шаблоне заменяет `if`. Медленные запросы — те, где одиннадцатое поле больше 0,5 с:

```bash
$ awk '$11 > 0.5 {printf "%s %s %ss %s\n", $1, $6, $11, $7}' access.log
198.51.100.90 "GET 0.872s /api/orders
203.0.113.7 "GET 1.204s /api/orders
```

Полезные встроенные переменные: `NR` — номер строки во входе, `FNR` — номер строки в текущем файле, `NF` — число полей, `FS`/`OFS` — разделители на входе и выходе. `awk -F: '{print $1}' /etc/passwd` печатает имена пользователей, `awk -F, 'NR>1 {sum+=$3} END {print sum}' report.csv` суммирует третий столбец CSV без заголовка.

Важная оговорка про реализации: в Debian и Ubuntu по умолчанию стоит `mawk`, он быстрее, но не имеет расширений GNU: `gensub()`, `asort()`, `strftime()` могут отсутствовать. Если нужен `gawk`, его ставят явно и вызывают по имени.

## jq: JSON как поток

`jq` — фильтр для JSON: на вход документ, на выход результат выражения. Точка `.` — весь документ, `.items` — поле, `.items[]` — поток элементов массива, `.a.b[0]` — вложенный доступ.

```bash
$ jq -r '.items[] | select(.status=="failed") | "\(.id) \(.dur)s"' deploy.json
r102 44s
r104 31s
```

`-r` выводит сырые строки без кавычек — это то, что нужно для передачи в другие команды. `-c` печатает компактно, одной строкой на документ — удобно для `while read`.

Агрегаты собираются почти как в функциональном языке:

```bash
$ jq '[.items[].dur] | {n: length, total: add, avg: (add/length)}' deploy.json
{
  "n": 4,
  "total": 95,
  "avg": 23.75
}
$ jq '[.items[]] | group_by(.status) | map({status: .[0].status, n: length})' deploy.json
[
  {
    "status": "failed",
    "n": 2
  },
  {
    "status": "ok",
    "n": 2
  }
]
```

`--arg name value` передаёт строку из шелла в фильтр без риска инъекции: `jq -r --arg e prod '.app + "@" + $e' deploy.json` вернёт `orders@prod`. `--argjson` передаёт уже готовый JSON.

Проверка в скрипте: `jq -e '.items | length > 0' deploy.json` вернёт 0, если выражение истинно и не `null`/`false`, и 1 иначе — это готовое условие для `if`. Для потоковой обработки NDJSON используйте `jq -c '. | {id, status}'` построчно; `-s` (slurp), наоборот, собирает весь вход в один массив, что на гигабайтах съест память.

## find и xargs

`find` обходит дерево и печатает или обрабатывает найденное. Порядок аргументов важен: выражения объединяются неявным `-a` (И), `-o` (ИЛИ) требует скобок.

```bash
$ find logs -name 'app*.log' -type f
logs/app 1.log
logs/app 3.log
logs/app 2.log
$ find logs -name '*.log' -mtime +7 -print
logs/old.log
```

`-mtime +7` — «изменён более 7 суток назад» (целые сутки), `-mmin -30` — минуты, `-size +100M` — размер. `-delete` удаляет найденное; обязательно ставьте `-type f` и узкий `-name`, иначе одна опечатка в выражении удалит лишнее. Безопасный порядок — сначала посмотреть `-print`, потом заменить на `-delete`.

`-exec команда {} \;` запускает команду на каждый файл, `-exec команда {} +` собирает файлы в один вызов — второй вариант на порядок быстрее и почти всегда предпочтительнее. Разница как между `xargs -n1` и `xargs` без ограничения.

`xargs` превращает stdin в аргументы. Без `-0` он режет вход по пробелам и ломается на именах с пробелами; с `-0` читает NUL-разделённый поток от `find -print0`:

```bash
$ find logs -name 'app*.log' -print0 | xargs -0 -n1 -P3 sh -c 'printf "[%s]\n" "$1"' _
[logs/app 1.log]
[logs/app 3.log]
[logs/app 2.log]
```

`-P3` — три параллельных процесса, `-n1` — один аргумент на запуск, `_` — подстановка `$0` для `sh -c`. Параллелизм полезен для сетевых операций (скачивание, `curl`), но не для записи в один файл: порядок вывода не гарантирован. `xargs` возвращает 123, если хоть один вызов завершился с ошибкой, и 124, если команда вернула 255 — это надо учитывать в скриптах с `set -e`.

## Конвейер реальной задачи

Задача: по логу доступа за минуту найти долю ошибок 5xx, самый медленный путь и общий трафик.

```bash
#!/usr/bin/env bash
set -euo pipefail

LOG=${1:?укажите путь к логу}
total=$(wc -l < "$LOG")
err=$(grep -cE '" 5[0-9]{2} ' "$LOG" || true)
pct=$(awk -v e="$err" -v t="$total" 'BEGIN {printf "%.2f", (t ? e*100/t : 0)}')

echo "всего запросов: $total"
echo "ошибок 5xx: $err (${pct}%)"
echo "самый медленный:"
awk '{print $11, $7}' "$LOG" | sort -nr | head -1

echo "трафик по кодам:"
awk '{b[$9] += $10} END {for (s in b) printf "  %s: %.1f KB\n", s, b[s]/1024}' "$LOG" | sort
```

```
всего запросов: 10
ошибок 5xx: 2 (20.00%)
самый медленный:
1.204 /api/orders
трафик по кодам:
  200: 2.0 KB
  201: 0.3 KB
  204: 0.0 KB
  304: 0.0 KB
  404: 0.1 KB
  500: 0.0 KB
```

`grep -c` возвращает 1, когда совпадений нет, и `set -e` убил бы скрипт — поэтому `|| true` здесь не костыль, а осознанная обработка штатного кода. `awk -v` передаёт значения из шелла в программу, не собирая её конкатенацией строк, — это защищает от поломки на кавычках в данных.

## Чего не делать

**Не парсите `ls`.** Вывод `ls` зависит от локали, флагов и типа терминала; имена с пробелами и переводами строк ломают разбор. Для обхода файлов есть glob и `find -print0`.

**Не grep-айте двоичные файлы без нужды.** `grep -r` по каталогу с `.so` и архивами печатает `Binary file ... matches` и тратит время. `-I` или `--include` решают проблему.

**Не используйте `cat file | grep pattern`.** Это лишний процесс: `grep pattern file` делает то же самое. `cat` оправдан только при склейке нескольких файлов.

**Не считайте `wc -l` числом строк в файле без завершающего перевода.** Он считает символы `\n`: файл из одной строки без `\n` в конце даст 0.

**Не доверяйте `sort` по умолчанию для чисел.** `sort` лексикографический, поэтому `10` идёт перед `9`. Нужен `sort -n`, для версий — `sort -V`, для людей — `sort -h`.

**Не редактируйте конфиги регуляркой без проверки.** `sed -i` не валидирует результат. Сначала `sed` в stdout, потом `diff`, потом `-i`.

## Типичные ошибки

1. **`grep` под `set -e`.** Механизм: «не найдено» — код 1. Скрипт падает там, где должен был продолжить. Лечится `if grep -q`, `|| true` или `grep -c ... || true`.
2. **`xargs` без `-0`.** Механизм: вход режется по пробелам и кавычкам, имя `app 1.log` становится двумя аргументами. Нужен `find -print0 | xargs -0`.
3. **`awk` без явного разделителя на CSV.** Механизм: по умолчанию `FS` — пробелы, вся строка становится одним полем `$1`. Нужен `-F,` и учёт кавычек в значениях (для настоящего CSV — специализированный инструмент).
4. **Порядок вывода ассоциативного массива.** Механизм: awk не хранит порядок ключей, jq сохраняет порядок входа, но `group_by` сортирует. Без `sort` вывод нестабилен и «прыгает» между запусками.
5. **`sed -i` на симлинке или в контейнере с read-only слоем.** Механизм: GNU sed заменяет файл новым, симлинк превращается в обычный файл; в read-only ФС — `Device or resource busy`. Проверяйте `-L` и точку монтирования.
6. **`find -delete` без `-type f`.** Механизм: под выражение попадают каталоги, и `-delete` удаляет их рекурсивно в порядке обхода. Сначала `-print`.
7. **`jq` без `-e` в условии.** Механизм: `jq` возвращает 0, даже если результат `null` или `false`, — проверка «поле есть и истинно» молча проходит. Нужен `jq -e`.

## Чек-лист

- Для поиска указаны ограничения: `--include`, `--exclude-dir`, `-I`.
- Коды возврата `grep` (0/1/2) учтены в скрипте, а не подавлены бездумно.
- `sed -i` применяется после проверки вывода в stdout и, при необходимости, с бэкапом.
- В awk задан `FS`, а вывод отсортирован, если порядок важен.
- JSON обрабатывается через `jq`, а не `grep`/`sed`; в условиях используется `-e`.
- Списки файлов передаются через `-print0` и `xargs -0` (или `-exec ... +`).
- `find -delete` предварён прогоном с `-print` и содержит `-type f`.
- Числовая сортировка выполняется с `-n`/`-V`/`-h`, а не по умолчанию.

## Упражнения

1. Из файла `/etc/passwd` получите список имён пользователей с UID ≥ 1000, отсортированный по UID. Сделайте это одной командой `awk` без `sort` и объясните, почему без `sort` порядок не гарантирован.
2. Постройте отчёт по логу: для каждого IP — число запросов, число 5xx и максимальное время ответа. Отсортируйте по числу 5xx по убыванию.
3. Напишите `sed`-выражение, которое превращает `key = value` в `KEY=value` (ключ в верхнем регистре, пробелы убраны). Проверьте на строках с комментариями и пустыми значениями.
4. Есть NDJSON-файл, по одному объекту на строку. Через `jq` выведите суммарное время по каждому `env`, затем через `xargs` передайте список `id` упавших сборок в команду `curl -fsS -X POST`.
5. Найдите в `/var/log` все файлы старше 14 дней, посчитайте их суммарный размер, затем удалите их, используя только `find` и `xargs` с NUL-разделителем. Оформите как скрипт с `DRY_RUN`.
