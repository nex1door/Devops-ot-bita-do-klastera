# Глава 17. Синтаксис и типы: коллекции, срезы, comprehension

Python — язык с динамической типизацией: переменная не имеет типа, тип имеет объект, на который она ссылается. Из этого вытекает почти всё, что раздражает новичков и экономит время опытным: изменяемость объектов, разделяемые ссылки, хешируемость, поведение `is` и `==`. В DevOps-коде Python чаще всего работает с чужими данными — JSON из API, выводом `kubectl`, конфигами, метриками, — и большинство инцидентов «скрипт сделал не то» сводится к непониманию устройства `list`, `dict` и `str`.

Глава даёт рабочую модель типов: числа и их точность, строки и байты, четыре базовые коллекции и их стоимость, распаковка, генераторы, аннотации. Все примеры проверены на CPython 3.14.9; вывод приведён дословно.

## Числа: int без переполнения, float с потерей точности

`int` в Python — длинная арифметика: переполнения нет, но есть цена. `2 ** 100` даёт `1267650600228229401496703205376` — корректный результат, а не мусор. Обратная сторона — запрет на гигантские преобразования в строку: с Python 3.11 действует лимит 4300 цифр для `int` ↔ `str`, чтобы не подвешивать процесс.

```python
import sys
print(sys.get_int_max_str_digits())      # 4300
str(10 ** 5000)
```

```text
ValueError: Exceeds the limit (4300 digits) for integer string conversion;
use sys.set_int_max_str_digits() to increase the limit
```

Это ровно тот класс проблем, который в проде выглядит как «процесс завис на обработке ответа». Лимит поднимается через `sys.set_int_max_str_digits()`, но чаще правильнее не считать факториалы в веб-обработчике.

`float` — IEEE-754 двойной точности, 53 бита мантиссы, отсюда `0.1 + 0.2 == 0.30000000000000004`. Для денег и квот, где важна десятичная точность, берут `decimal.Decimal` или `fractions.Fraction`: `Decimal("0.1") + Decimal("0.2")` даёт ровно `0.3`, а `Fraction(1, 3) + Fraction(1, 6)` — `1/2`.

Деление `/` всегда возвращает `float`, целочисленное — `//`, остаток — `%`, а `divmod` отдаёт оба сразу:

```python
print(7 / 2, 7 // 2, 7 % 2, divmod(7, 2))
```

```text
3.5 3 1 (3, 1)
```

Отдельный сюрприз — `round()`: это банковское округление (half to even). `round(2.5)` → `2`, `round(3.5)` → `4`. Для метрик неважно, для биллинга критично.

## Строки: неизменяемые последовательности Unicode

`str` — последовательность кодовых точек Unicode, неизменяемая. Методы возвращают новые строки; `s.upper()` без присваивания результата — типичный no-op.

f-строки (formatted string literals) — основной инструмент форматирования: внутри `{}` допустимы выражения, спецификация формата после `:` и отладочный суффикс `=`:

```python
name, p95 = "api-gateway", 128.4567
print(f"{name}: p95={p95:.1f} ms")
print(f"{name=} {p95=}")
print(f"{255:#06x} {0.834:>8.1%} {1234567:,}")
```

```text
api-gateway: p95=128.5 ms
name='api-gateway' p95=128.4567
0x00ff    83.4% 1,234,567
```

Суффикс `=` печатает выражение вместе со значением — быстрый способ отладки. Формат после `:` читается как `[[fill]align][sign][width][,][.precision][type]`: `>8.1%` — вправо в поле 8 символов, один знак после запятой, умножение на 100.

Срезы работают по схеме `s[start:stop:step]`, где `stop` не включается, а отрицательные индексы считаются с конца:

```python
s = "cluster"
print(s[0], s[-1], s[2:5], s[::-1], s[::2])
```

```text
c r ust retsulc cutr
```

Срез не бросает `IndexError` при выходе за границы — он усекается: `s[100:]` вернёт пустую строку, и ошибка всплывёт позже, там, где пустое значение не ожидали.

Байты (`bytes`) — отдельный тип. `len("кластер")` равно 7 (символы), а `len("кластер".encode())` — 14 (байты {{L|g125|UTF-8}}, по два на кириллическую букву). Смешивать их нельзя: конкатенация `str` и `bytes` бросает `TypeError`. Чужой поток декодируют с явной политикой: `raw.decode("utf-8", errors="replace")` не упадёт на битом байте, но подменит символ.

## Четыре коллекции и их стоимость

| Коллекция | Упорядоченность | Изменяемость | Поиск | Хешируемость |
|---|---|---|---|---|
| `list` | да, по индексу | да | O(n) | нет |
| `tuple` | да, по индексу | нет | O(n) | да, если элементы хешируемы |
| `dict` | да, порядок вставки | да | O(1) в среднем | нет |
| `set` | нет | да | O(1) в среднем | нет |

`dict` с Python 3.7 гарантирует порядок вставки — это часть спецификации языка, а не деталь реализации. `set` порядок не гарантирует: `list({"b": 1, "a": 2})` даёт `['b', 'a']`, а порядок элементов множества может меняться между запусками.

Разница в стоимости принципиальна. Замер на 100 000 элементов:

```python
import timeit
setup = "d = {i: i for i in range(100_000)}; l = list(range(100_000))"
print(timeit.timeit("d[99_999]", setup, number=1_000_000))
print(timeit.timeit("99_999 in l", setup, number=1_000))
```

```text
0.0379
1.0921
```

Миллион обращений к словарю — 38 мс, около 40 нс на операцию. Тысяча проверок `in` по списку — 1,09 с, примерно 1,1 мс на проверку. Отношение — четыре порядка. Вывод: если в цикле есть `if item in collection` и `collection` — список длиннее нескольких десятков элементов, это `set`.

Проверка `x in list` выполняет `==` поэлементно, `x in set` — хеширование и поиск в таблице, поэтому `set` требует хешируемых элементов: `{[1, 2]}` бросает `TypeError: unhashable type: 'list'`. Кортеж из хешируемых элементов хешируем: `(1, 2) in {(1, 2), (3, 4)}` → `True`.

```python
a = {"web-1", "web-2", "web-3"}
b = {"web-2", "web-3", "web-4"}
print(sorted(a & b), sorted(a - b), sorted(a | b))
```

```text
['web-2', 'web-3'] ['web-1'] ['web-1', 'web-2', 'web-3', 'web-4']
```

Сортировка в примере не случайна: хеши строк рандомизируются при старте процесса (`PYTHONHASHSEED`), поэтому порядок обхода множества меняется от запуска к запуску и делает `diff` двух выгрузок бессмысленным.

## Изменяемость, алиасы и ловушка аргумента по умолчанию

Присваивание в Python не копирует объект, а связывает имя со ссылкой. `b = a` для списка — два имени на один объект; изменение через любое имя видно через оба. Копия — это `a[:]`, `a.copy()`, `list(a)`, а для вложенных структур — `copy.deepcopy(a)`.

```python
a = [1, 2, 3]
b = a
b.append(4)
print(a)          # [1, 2, 3, 4]
c = a[:]
c.append(5)
print(a, c)       # [1, 2, 3, 4] [1, 2, 3, 4, 5]
```

Та же модель объясняет классическую ловушку: значение по умолчанию вычисляется **один раз**, при определении функции, и сохраняется в объекте функции.

```python
def add_tag(tag, tags=[]):
    tags.append(tag)
    return tags

print(add_tag("a"), add_tag("b"))
```

```text
['a', 'b'] ['a', 'b']
```

Оба вызова вернули один и тот же список: первый дописал `"a"`, второй — `"b"`. В продакшене это выглядит как «накопление» меток, заголовков, соединений между запросами — утечка состояния через общий объект. Идиома — `None` как сигнал «не передали»:

```python
def add_tag_ok(tag, tags=None):
    tags = [] if tags is None else tags
    tags.append(tag)
    return tags

print(add_tag_ok("a"), add_tag_ok("b"))
```

```text
['a'] ['b']
```

Правило шире, чем список: любой изменяемый объект в значении по умолчанию (`list`, `dict`, `set`, экземпляр класса) разделяется между вызовами. Неизменяемые (`None`, числа, строки, кортежи из неизменяемых) безопасны.

## Распаковка и слияние

Распаковка заменяет индексацию и одновременно служит валидацией формы данных: несовпадение количества элементов даёт `ValueError` сразу, а не через пять строк.

```python
host, port = ("10.0.0.5", 5432)
first, *rest = [1, 2, 3, 4]
print(host, port, first, rest)
```

```text
10.0.0.5 5432 1 [2, 3, 4]
```

Звёздочка собирает «остаток» в список, и такая распаковка допустима один раз в выражении. Для словарей работает `**`, а с Python 3.9 есть оператор `|`:

```python
cfg = {"host": "db", "port": 5432}
print({**cfg, "port": 6432})        # {'host': 'db', 'port': 6432}
print({**{"timeout": 3}, **cfg})    # {'timeout': 3, 'host': 'db', 'port': 5432}
print(cfg | {"port": 6432})
```

Порядок важен: правый словарь перекрывает левый. Это стандартный способ собрать конфиг «значения по умолчанию + переопределения», но он поверхностный — вложенные словари заменяются целиком, а не сливаются рекурсивно.

## Comprehension и генераторы

List comprehension — выражение, а не цикл: оно строит список целиком и сразу. Generator expression строит ленивый итератор, который вычисляет элементы по требованию.

```python
import tracemalloc

tracemalloc.start()
data = [i * i for i in range(1_000_000)]
print(f"{tracemalloc.get_traced_memory()[1] / 1024 / 1024:.1f} MiB")
del data
tracemalloc.reset_peak()
tracemalloc.stop()

tracemalloc.start()
gen = (i * i for i in range(1_000_000))
print(f"{tracemalloc.get_traced_memory()[1] / 1024:.0f} KiB")
tracemalloc.stop()
```

```text
38.6 MiB
0 KiB
```

Список занимает 38,6 МиБ, генератор — 0 КиБ по счётчику (меньше блока учёта): он хранит только текущий элемент и позицию. Если данные не нужны все сразу (сумма, максимум, потоковая запись), генератор предпочтителен; если нужен произвольный доступ или повторный проход — список.

Тело генераторной функции не выполняется до первого `next()`; каждый `yield` приостанавливает выполнение и сохраняет локальное состояние. Отсюда класс ошибок: генератор одноразовый — второй проход по исчерпанному генератору не даст ничего. Подробно `yield` разобран в главе 18.

Comprehension бывает не только для списков: `{k: v for ...}` даёт словарь, `{x for ...}` — множество. Условие `if` и вложенные циклы допустимы, но два условия и более делают выражение нечитаемым — тогда нужен обычный цикл.

## `is` против `==`

`==` сравнивает значения через `__eq__`, `is` — идентичность объектов (один и тот же адрес). Для `None` правильно `is None`: это одна константа на процесс, и `is` нельзя переопределить. Для чисел и строк `is` даёт неопределённый результат, зависящий от кеширования:

```python
a = int("257"); b = int("257")
print(a == b, a is b)
print(256 is 256)
```

```text
True False
True
```

Малые целые от −5 до 256 кешируются интерпретатором, поэтому `256 is 256` истинно, а результат для 257 зависит от того, создан ли объект один раз (константа в коде) или дважды (вызов `int`). Python 3.14 к тому же выдаёт `SyntaxWarning` на `is` с литералом. Правило: `is` — только для `None`, `True`, `False` и явных сигнальных объектов.

## Хешируемость и собственные ключи

Ключ словаря или элемент множества обязан иметь стабильный `__hash__`, согласованный с `__eq__`: если `a == b`, то `hash(a) == hash(b)`. По умолчанию класс наследует `__eq__` (сравнение по идентичности) и `__hash__` (по адресу) от `object`, что согласовано. Как только вы определяете `__eq__`, Python обнуляет `__hash__`, и экземпляр становится нехешируемым — защита от нарушения контракта.

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x, self.y = x, y

    def __eq__(self, other):
        return (self.x, self.y) == (other.x, other.y)

    def __hash__(self):
        return hash((self.x, self.y))

print(Point(1, 2) in {Point(1, 2)})
```

```text
True
```

Без `__hash__` последняя строка бросила бы `TypeError`. И обратное правило: объект-ключ не должен меняться после вставки — иначе хеш «уплывёт» и запись станет недостижимой. `__slots__` здесь про память: у экземпляра нет `__dict__`, экономия на миллионах объектов заметна, но появляются ограничения.

## Аннотации типов

Аннотации — синтаксис, а не проверка времени выполнения: интерпретатор их сохраняет и не проверяет. Проверяют внешние инструменты — `mypy`, `pyright`, `pyre`. В DevOps-коде аннотации документируют контракты обработчиков и ловят несовпадение `dict`/`list` до запуска.

```python
from typing import Literal, Optional

def retry(times: int, backoff: Literal["linear", "exp"] = "exp") -> list[float]:
    return [0.0] * times

def find_node(name: str) -> Optional[str]:
    return name if name.startswith("node-") else None

print(Optional[int], list[int])
```

```text
int | None list[int]
```

С Python 3.9 встроенные generic-типы (`list[int]`, `dict[str, int]`, `tuple[int, ...]`) пишутся без `typing.List`. С Python 3.10 `Optional[X]` и `Union[X, Y]` заменяются на `X | None` и `X | Y`, и именно эту форму показывает `repr`. `Optional[T]` означает «T или None», а не «необязательный аргумент»: необязательность задаётся значением по умолчанию, а не типом.

`Literal` фиксирует допустимый набор значений и превращает опечатку в ошибку типизации, а не в `KeyError` в проде. Для словарей с известной схемой используют `TypedDict` или `dataclass`; для «словаря произвольных ключей» — `dict[str, object]`, и это честно говорит, что дальше нужна валидация на границе системы.

Отдельная деталь: `from __future__ import annotations` больше не нужен — в 3.14 отложенное вычисление аннотаций работает по умолчанию (PEP 649/749), а `typing.get_type_hints()` разрешает строки в реальные объекты, когда это требуется.

## Типичные ошибки

1. **Изменяемое значение по умолчанию.** `def f(x, acc=[])` создаёт список один раз при определении функции; все вызовы делят его. Механизм: значение по умолчанию вычисляется при выполнении `def` и живёт в `f.__defaults__`. Лечение — `None` плюс создание внутри.
2. **`is` вместо `==` для значений.** Кеш малых целых и интернирование строк делают результат `is` зависящим от контекста; сравнение «работает» на тестах и ломается на данных из сети. `is` — только для синглтонов.
3. **Список как ключ словаря.** `{[1, 2]: "x"}` бросает `TypeError`: список изменяем, его хеш не может быть стабильным. Решение — кортеж или `frozenset`.
4. **`a = b` вместо копии.** Для списков, словарей и множеств это алиас; правка «копии» меняет оригинал, потому что присваивание связывает имена с объектом. Копия — `copy()`, срез или `deepcopy`.
5. **Генератор, прочитанный дважды.** После исчерпания он не перезапускается и молча даёт пустоту; сумма по нему оказывается нулём. Механизм — итератор хранит позицию и не имеет операции сброса.
6. **`str` и `bytes` вперемешку.** Чтение файла в бинарном режиме и передача результата в функцию, ожидающую `str`, даёт `TypeError` или «кракозябры». Механизм — разные типы и разные единицы длины.

## Чек-лист

- [ ] Для проверок вхождения в коллекцию больше ~50 элементов используется `set` или `dict`, а не `list`.
- [ ] Ни одна функция не имеет изменяемого значения по умолчанию; проверено `grep` по `def .*=\[\]` и `={}`.
- [ ] Все сравнения с `None` — через `is None` / `is not None`; `is` не применяется к числам и строкам.
- [ ] Копирование конфигов и вложенных структур — явное (`copy`, `deepcopy`), а не присваивание.
- [ ] Генераторы не переиспользуются: если нужен второй проход, материализован список.
- [ ] Кодировка при `open()` и `decode()` указана явно, политика `errors` выбрана осознанно.
- [ ] Публичные функции имеют аннотации, и `mypy --strict` (или `pyright`) проходит без новых ошибок.
- [ ] `Literal`/`TypedDict` использованы там, где набор значений или ключей фиксирован, вместо «голого» `str` и `dict`.
